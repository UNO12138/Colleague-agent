# Colleague Agent

一个探索「主任务进度、协助代理交流与阶段性可视化」的网页和 Electron 桌面原型。当前已接入 Codex 的真实对话会话；任务执行事件与进度可视化仍在设计阶段。

## 目前能体验什么

- **协作对话**：新对话选择 Codex 后，任务规划与后续消息由本机 Codex 会话处理，使用 `gpt-5.6-luna`；每个新建对话的确认状态、步骤进度、任务卡、消息历史、待处理决定和交付信息会在本机保存，重启窗口后按会话恢复。预设的首个情境对话继续使用原演示流程。
- **生成式 UI 阶段预览**：手动生成阶段 Markdown，再由视觉协助代理从七种固定版式中选择一种，以原文块为依据展示。可查看预览样例、重新生成草稿，并在本机恢复已保存的阶段结果。周二汇报预设情境的 24 条旧阶段记录随便携版提供，其中 10 条符合当前界面格式、可离线显示对应预览；它们明确标为离线情境存档，不代表接收设备上的主 Agent 已执行任务。
- **最终文件演示**：结束模拟任务时，可根据阶段草稿生成 Word 报告；只有服务端返回实际文件路径后才显示交付文件卡。
- **工具页界面**：展示 Codex、Hermes Agent、Deepseek Harness 和 Kimi Code 的本地代理列表、搜索、状态按钮与管理弹窗。Codex 登录状态来自本机应用服务；其他代理状态及启动、卸载、自动启动等管理操作仍是界面演示。
- **桌面窗口**：Electron 使用与网页相同的页面；各视图共用侧栏和毛玻璃窗口底层。

### 必须区分的事实

选择 Codex 的新对话，其规划与即时回复来自真实 Codex 会话。点击「生成真实草稿」时，Codex 会为当前步骤执行只读调查，保存命令、网页搜索、工具调用等可观察行动及阶段原文；DeepSeek 读取行动记录和原文建议版式。页面显示执行状态、行动数量及最近一项行动。其他代理选项仍由 DeepSeek 演示适配层处理。工作卡片的步骤推进仍由原型情境和手动操作控制，不能视为真实 Codex 执行进度。工具页中非 Codex 的代理状态也是演示数据。

## 本地运行

### 网页临时 API

在线网页的「工具 → 云端」可输入用户自己的 DeepSeek API 密钥，进行单次提问；网页对话使用该临时 API 生成任务规划、即时回复和阶段草稿，并可下载 Markdown 报告草稿。已存在的预设对话可点「用 AI 生成规划」更新原有规划。密钥只留在当前页面的内存中，不写入本地存储或服务器；刷新、关闭页面后需重新输入。每次对话请求只发送本次输入与当前任务规划、进度，不附带聊天历史；阶段请求发送当前任务说明与步骤，报告请求发送当前任务说明与本页已生成的阶段草稿。网页界面的对话记录仍按原有机制保存在浏览器本地存储。请求由浏览器直接发往 DeepSeek，会消耗密钥对应账户的额度；临时 API 不具备本机 Codex 的工具执行能力。阶段草稿只在本页内存中保留，刷新后需要重新生成。

需要 Node.js、pnpm 和可运行 Electron 的桌面环境。在本目录安装依赖：

```bash
pnpm install
```

| 目标 | 命令 | 说明 |
| --- | --- | --- |
| 只看网页界面 | `pnpm dev` | 打开 `http://127.0.0.1:5173/`；不启动本地模型适配层 |
| 网页与本地模型适配层 | `pnpm dev:demo` | 同时启动网页和 `http://127.0.0.1:8787` 上的适配层 |
| Electron 开发窗口 | `pnpm dev:desktop` | 同时启动网页开发服务和桌面窗口；窗口会启动本地适配层 |
| 单独启动桌面程序 | `pnpm start` | 直接加载本地页面；多视图开发与验收建议使用上一项 |

### 发给其他 Windows 设备

运行 `pnpm package:win`，然后把 `release/Alex-Colleague-Agent-Windows.zip` 发给组员。对方需要完整解压，再双击其中的 `Alex Colleague Agent.exe`；无需安装 Node.js 或 pnpm。压缩包不包含打包者的密钥、聊天记录和阶段产物，各设备将这些数据保存在自己的 Windows 用户数据目录。此便携版没有代码签名，Windows 可能提示确认运行。

Codex 实际对话要求接收设备自行安装并登录 Codex 命令行；DeepSeek 阶段生成要求接收设备在「工具 → Deepseek Harness → 配置接口」填写自己的接口密钥。密钥只保存在该设备的用户数据目录，不进入压缩包。缺少这些连接时，预设的周二汇报情境、写好的离线对话及阶段界面存档仍可体验；新的真实模型调用不可用。`scenario-archive/` 只含该预设情境的阶段草稿和生成式界面记录，新建对话的私人记录不会随包分发。

本项目同时保留 `package-lock.json` 和 `pnpm-lock.yaml`。以上命令以 pnpm 为例；请按所选包管理器的锁文件安装，避免混用导致依赖记录变化。`dev` 仅供本地预览，不会发布网站。

### 使用 DeepSeek 模型

在项目根目录创建不提交到 Git 的 `.env.local`：

```text
DEEPSEEK_API_KEY=你的密钥
```

本地适配层默认使用 `deepseek-v4-flash`；可用 `DEEPSEEK_MODEL` 覆盖，也可用 `COLLEAGUE_AGENT_PORT` 改端口。前端当前默认访问 `127.0.0.1:8787`，改端口时还需同步调整前端地址。Electron 启动时会尝试启动本地适配层；仅运行 `pnpm dev` 时，如需调用模型，应另开终端执行 `pnpm agent`，或直接使用 `pnpm dev:demo`。

密钥缺失或模型服务不可用时，意图交流可回退到本地规则；这只保障演示可继续，不代表模型判断成功。阶段草稿生成失败会显示错误和重试入口，不会伪装成真实生成结果。

### 使用 Codex · GPT-5.6 Luna

先在本机安装 Codex 命令行并执行 `codex login`。运行 `pnpm dev:desktop` 或 `pnpm dev:demo`，在「新对话」选择 Codex 后即可使用。网页只运行 `pnpm dev` 时，本地代理接口不会启动。Codex 使用本机 ChatGPT 登录，不需要在此项目填写 API 密钥。

本地服务通过 Codex 应用服务建立会话、发送消息，并把会话标识保存在浏览器本地存储中；刷新页面或重启服务后可继续同一会话。模型固定为 `gpt-5.6-luna`，推理强度为「低」。当前接入处于只读模式，不执行文件修改或命令审批。即时对话连接失败会明确报错，不会伪装成 Codex 回复。阶段生成时，服务端按顺序收集 Codex 完成的可观察行动，连同阶段原文保存在 `runtime-artifacts/`；本地任务要求实际读取输出，联网任务启用网页搜索并要求结果附来源网址。DeepSeek 读取行动记录和原文选择生成式 UI 的版式。若 Codex 在 30 秒内没有返回任何行动，该阶段切换到原有 DeepSeek 演示生成，产物明确标为未经 Codex 执行核实；已开始行动却未取得有效证据时仍报错。网页搜索事件能证明发起了搜索，但目前不能单凭事件证明链接里的每一项表述都经过独立事实核查。这里获取的是外显事件与产物，不是模型内部的完整推理文字。最终报告仍使用原有 DeepSeek 流程。

## 生成式 UI 如何工作

1. 用户确认任务后，工作卡片显示当前步骤。Codex 对话点击「生成真实草稿」时，服务端在同一个 Codex 会话中执行当前步骤的只读调查，并保存完成的行动、轮次编号和阶段 Markdown。本地磁盘任务禁止默认递归扫描整盘，先获取可快速核实的数据；30 秒没有任何行动时切换到明确标注的演示生成，已经开始取数却缺少有效证据时直接报错。
2. 其他演示代理仍将当前界面快照交给 DeepSeek 生成阶段 Markdown。阶段产物保存在被 Git 忽略的 `runtime-artifacts/`。
3. 服务端解析标题、段落、要点和表格。视觉协助代理只建议模板和原文块编号，服务端再校验并执行版式回退。
4. 前端通过固定组件展示摘要、分类卡片、对比矩阵、数字图表、环形图、流程或画布。布局模型不能直接生成任意网页代码。

分类内容优先卡片，非数字对比表使用矩阵；摘要只适合单一连续叙述。数量上限、图表判断和其他具体限定见[生成式 UI 范围与限定](./GENERATIVE_UI_CONSTRAINTS.md)。阶段原文、预览和最终文件是不同产物；预览可能只呈现部分原文内容。

## 当前未完成的部分

- Codex 的只读命令与网页搜索事件已接入手动触发的阶段生成；这些事件尚未成为自动推进工作卡片的依据。当前步骤进度仍为演示状态。
- 阶段预览尚无逐条证据到原文及界面块的完整来源映射，也没有自动事实核查。
- 工具页的云端列表尚未设计完成；本地代理管理操作也未连接真实进程或账户。
- 本机阶段结果按会话和步骤标题恢复。步骤更名、清理运行目录或跨设备迁移后，当前不能保证恢复。
- 版式单元测试不能代替完整的端到端视觉与事实验收。
