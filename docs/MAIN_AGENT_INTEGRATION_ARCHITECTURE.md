# 主进程代理接入：界面与架构草案

更新：2026-09-28。此文是设计方案，不代表当前原型已实现。产品目标是让现有程序成为编码代理的可视化界面，可在独立桌面窗口运行，并逐步进入编辑器。

## 核心定位

当前程序负责**看见、理解、审阅和控制**一次任务。真正执行代码修改、命令与工具调用的仍是所连接的编码代理。界面不根据文字猜测“步骤已完成”，而是消费代理发出的真实事件，并保留事件出处。

本轮工具页只保留**主进程代理**入口，用于选择谁来执行任务，以及如何连接、授权、恢复会话。其他工具能力不进入当前界面范围。

## 推荐结构

```text
编辑器扩展 / 终端启动命令 / 独立桌面窗口
                    ↓
             同一套视觉界面
                    ↓
       本地会话协调层与事件记录
                    ↓
           统一的代理适配接口
          ↙          ↓          ↘
   Codex 专用适配器  开放协议适配器  其他专用适配器
          ↓          ↓          ↓
        各自的编码代理与真实工作环境
```

视觉界面只依赖统一事件，不直接解析终端彩色输出或依赖某一家代理的字段。适配器负责启动或连接代理、建立会话、发送用户输入、接收流式事件、转交审批、恢复会话，以及报告该代理实际支持的能力。

## 统一接口的最小内容

| 类别 | 至少需要的信息 |
| --- | --- |
| 连接能力 | 可启动、可附着现有会话、可恢复、可中断、可读取历史、可请求审批、可获得文件差异和阶段产物；不支持时明确标注。 |
| 会话身份 | 本地连接标识、提供方会话标识、项目目录、工作环境、创建时间。 |
| 实时事件 | 会话开始、用户输入、代理回复、步骤开始与结束、命令运行、文件修改、工具调用、审批请求、错误、连接中断、任务结束。 |
| 事件证据 | 提供方原始事件标识、时间、顺序、来源、关联的会话和轮次；允许用户查看原始依据。 |
| 控制动作 | 发消息、暂停或中断、继续、批准或拒绝、打开产物；每个动作只能在提供方支持时显示。 |

界面状态从事件推导。例如显示“验证中”需要真实的检查事件；仅收到代理一句“我会检查”不能把状态改为验证中。断线后依据持久化事件恢复，避免重复显示或丢失审批请求。

## 三种运行形态

1. **独立桌面窗口**：现有程序继续作为完整工作台；本地协调层连接在本机运行的编码代理。这是最适合先落地的形态，也能服务从终端启动的代理。
2. **编辑器内视图**：为目标编辑器编写轻量扩展，复用核心界面。扩展只提供项目目录、当前文件或选区、打开文件和差异等编辑器能力；会话协调与代理适配仍复用同一套核心逻辑。以 VS Code 为例，其扩展接口允许在侧栏或面板承载自定义网页视图。[官方文档](https://code.visualstudio.com/api/ux-guidelines/webviews)
3. **终端配套模式**：在终端用命令启动或连接会话，同时打开独立窗口或本地网页查看过程。普通终端不能保证承载完整图形界面；它是启动和控制入口，不应成为视觉界面的唯一容器。

## 接入顺序

**第一步：Codex 专用适配器。** Codex 的应用服务公开会话、轮次、事件流和审批请求；本机默认可以通过标准输入输出通信。先跑通“创建会话 → 执行一轮 → 显示命令与文件变化 → 审批 → 完成 → 重启后恢复”。[OpenAI 官方文档](https://learn.chatgpt.com/docs/app-server)

**第二步：开放协议适配器。** 代理客户端协议旨在连接编辑器客户端与编码代理，可作为接入多个兼容代理的公共基础；具体实现仍需逐个检查支持的能力和版本。可用 Gemini 命令行代理的协议模式做第二个验证对象。[协议项目](https://github.com/agentclientprotocol/agent-client-protocol)、[Gemini 官方实现说明](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/acp-mode.md)

**第三步：专用适配器。** 某些代理只提供自有软件开发包、命令行流式输出或插件入口，需独立适配。若没有稳定的会话、审批和事件接口，只提供“只读观察”或“新建受控会话”，不能宣称可完整接管已有会话。

## 工具页的信息架构

主进程代理区域建议采用“已连接 / 可添加”两组卡片。每张卡片只显示：代理名称、连接状态、运行位置、当前项目、支持的关键能力，以及“连接 / 配置 / 查看会话”入口。详情页展示：连接方式、可执行文件或服务地址、认证状态、项目权限、能力清单、测试连接结果和错误信息。

本轮不展示其他工具或连接器的入口与占位卡片。

## 与当前原型的差距

现有 DeepSeek 本地适配层负责协助交流和生成阶段草稿，主任务步骤仍是模拟数据。下一阶段先增加真实代理事件进入会话协调层，再让工作卡片和生成式预览读取这些事件。阶段草稿可以继续由视觉协助代理整理，但必须标明原始事件与证据，不能把整理结果当作执行事实。

## 首轮验收

- 连续两轮对话能对应到同一个真实代理会话，刷新或重启后可恢复。
- 命令、文件变化、审批和结束状态与代理原始事件一致。
- 断线、拒绝审批、不支持的动作有明确界面反馈。
- 同一任务在独立窗口和编辑器视图中呈现相同的核心状态；编辑器视图可以打开对应文件与差异。
- 无需支持所有代理后再上线：先完整接入一种，再验证开放协议适配，最后扩展其他提供方。
