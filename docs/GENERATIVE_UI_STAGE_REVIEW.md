# 生成式 UI 阶段性总结与对接记录

更新：2026-09-28。依据当前原型代码和本地测试整理。本文件描述现状与待确认事项；旧规格中的目标状态不等于已实现状态。

## 一句话定位

目前是**有真实模型参与的生成式阶段预览原型**：模型生成阶段 Markdown，并从原文块中建议一种预设版式；前端用固定组件渲染。它尚不是接入真实主 Agent 执行轨迹、可自动核实资料的完整生成式 UI 系统。

## 当前链路

1. 用户确认任务后，工作卡片按当前步骤显示进度。步骤推进仍主要由原型按钮和固定情境逻辑控制。
2. 点击「生成真实草稿」时，前端提交任务 brief、步骤标题，以及从页面可见消息和卡片状态整理出的 `mainProcessData`。
3. 本地适配层调用 DeepSeek，生成阶段 Markdown；服务端先把原文写入 `runtime-artifacts/<id>/`。
4. 服务端把 Markdown 解析为标题、段落、要点和表格。视觉协作 Agent 只能选模板和原文块编号；`safeLayout` 再限制可用模板、块编号，并根据数字表格覆盖部分选择。
5. 前端的 `step-preview.js` 用固定组件渲染 `summary / cards / comparison / chart / donut / workflow / canvas` 等版式。刷新后可按会话 ID 恢复已保存的阶段预览。
6. 结束模拟任务时，可根据已保存的阶段草稿生成 Word 报告；只有服务端实际返回文件路径，界面才显示交付文件卡。

## 已有的边界与价值

- 内容与表现分离：Markdown 是阶段原文，布局 JSON 只保存模板与原文块引用，前端控制最终 DOM。模型不能直接生成任意 HTML。
- 视觉选择有回退：视觉模型失败时仍能用受限规则生成预览；失败原因记录在 `renderedBy`。这只保证可显示，不保证版式恰当。
- 文件与预览有状态区分：进行中不会显示虚构的最终文件；预览样例另有入口，并标明样例数据。
- 现有 `ASSISTANT_AGENT_SPEC.md` 和 `STATE_AND_UI_SPEC.md` 提供协助 Agent 与状态流的设计依据，但其中部分状态和完整接入仍属后续目标。

## 当前不能视为已完成的能力

- `mainProcessData` 是页面可见文本与模拟步骤组成的快照，并非真实主 Agent 的工具结果或经核查的资料来源。生成的 Markdown 是对输入的整理与推论，不能因此认定外部事实已经验证。
- 阶段草稿靠手动点击生成；推进步骤也有「模拟推进」入口。当前没有主 Agent 在真实执行节点自动产出结构化事件并触发预览。
- 缺少逐条证据到 UI 块的来源映射、事实校验与人工审阅门槛。视觉模型的块选择可追溯到 Markdown，但 Markdown 本身的事实来源没有完整链路。
- 目前的 JSON Schema 主要约束 `/agent` 的意图回复，与阶段预览的 `previewSchemaVersion=2` 不是同一份契约；阶段结果缺少独立、完整的外部协议文档。
- `runtime-artifacts` 是本机运行目录并被 Git 忽略；现有恢复按会话 ID 和步骤标题匹配，更名步骤、跨设备或清理目录后不能保证恢复。

## 2026-09-28 版式规则对齐

- 已确认：定性对比表展示为对比矩阵；没有表格时不使用对比矩阵；出现两个以上分类小节或并列要点时，优先展示分类卡片；摘要只用于单一、连续的结论或叙事。
- 规则、模型提示和要点卡片渲染已同步调整。`node --test stage-pipeline.test.cjs file-artifact.test.cjs`：10 项全部通过。尚未进行完整的界面视觉验收。
- README 仍写默认模型为 `deepseek-flash`，当前代码默认值为 `deepseek-v4-flash`。README 对阶段生成链路也未完整描述。
- 本地已有阶段运行产物，但其存在只证明生成与保存曾运行；本次未逐份核查内容准确性，也未做端到端视觉验收。

## 建议在此节点确认的口径

| 议题 | 建议口径 | 需要确认的选择 |
| --- | --- | --- |
| 生成式 UI 的定义 | 当前称为「基于阶段原文的受约束生成式预览」 | 是否同意此命名，避免把模拟主进程误称为真实任务执行 |
| 事实来源 | Markdown 必须标明输入快照和可核实证据；无证据时明确为分析草稿 | 下一阶段是否优先接真实主 Agent 事件与证据引用 |
| 版式控制 | 保留固定组件和服务端校验，模型只选模板及原文块；分类内容优先卡片，定性表格优先矩阵 | 七种模板是否作为当前设计范围 |
| 触发时机 | 当前手动生成用于调试；正式体验应在真实步骤产出时触发 | 是否保留手动「重新生成」作为调试入口 |
| 生命周期 | 阶段原文、布局、预览与最终交付应区分版本和状态 | 重生成是否覆盖展示版本、是否保留历史与审阅记录 |
| 验收标准 | 至少核对内容来源、布局适配、失败回退、刷新恢复和真实文件状态 | 哪些步骤必须由用户确认后才能进入最终交付 |

## 下一阶段最小闭环

1. 对已统一的版式规则进行界面视觉验收，并更新 README 中的实际运行链路及模型名。
2. 定义真实主 Agent 的阶段事件契约：会话与步骤 ID、原始证据、已完成状态、时间、来源、版本。
3. 在阶段 Markdown 和每个预览块之间建立证据引用；区分事实、推断和待核实内容。
4. 让真实阶段事件触发生成，保留手动重试与明确的生成失败状态。
5. 用定性摘要、非数字对比、同单位数字、混合单位、无数据、模型超时和步骤更名等案例做端到端验收。
