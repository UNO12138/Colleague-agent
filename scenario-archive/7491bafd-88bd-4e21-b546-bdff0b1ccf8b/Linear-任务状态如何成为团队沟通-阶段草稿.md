# Linear · 任务状态如何成为团队沟通（阶段草稿）

## 本阶段要回答的问题
Linear 的协作机制中，任务状态是否不只是进度标记，而是承担团队沟通与状态感知的载体。本阶段只拆解这一条主线，为后续与 Notion、Figma、Miro 的横向比较提供维度。

## 分析框架
拟从四个层面拆解：
1. **状态即信息**：状态字段本身承载哪些含义，是否替代部分口头同步。
2. **状态变更的可见性**：变更如何被团队感知，是否形成事件流。
3. **评论与状态的耦合**：讨论是否依附于任务与状态，而非独立存在。
4. **编辑行为的痕迹**：谁在何时改动了什么，是否可追溯。

## 待核实问题
- Linear 的状态集合与自定义空间：待核实。
- 状态变更是否默认通知相关成员、通知粒度如何：待核实。
- 评论与状态流转之间是否存在强制或推荐关联：待核实。
- 编辑历史与操作记录的保留范围：待核实。
- 上述机制在免费版与付费版之间是否有差异：待核实。
