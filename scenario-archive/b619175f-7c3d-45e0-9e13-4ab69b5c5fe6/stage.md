# 协作产品竞品调研 · 阶段草稿：Linear 的任务状态与团队沟通

## 本阶段的分析框架

本阶段聚焦 Linear，核心问题是：任务状态在 Linear 中如何从“个人进度标记”转化为“团队沟通信号”。我计划从三个层面拆解：状态的语义设计（有哪些状态、如何分类）、状态变更的可见性（谁在什么位置感知到变化）、以及状态与评论、负责人、周期等元素的耦合方式。这一框架后续会复用到 Notion、Figma、Miro 的对比中，但各产品的机制命名与边界需要分别核实。

## 待核实的问题

以下内容目前只是基于任务说明提出的假设，尚未通过实际访问产品、文档或用户反馈验证：

- Linear 的状态集合是否区分“未开始 / 进行中 / 已完成 / 已取消”等类别，以及是否存在按团队自定义的状态分组。
- 状态变更是否会触发对相关成员的主动通知，还是仅依赖列表、看板等视图的被动刷新。
- 评论与状态变更之间是否存在联动，例如状态回退时是否要求附注原因。
- 周期（Cycle）或项目视图是否承担了“团队级进度感知”的角色，与单个 issue 状态形成两层结构。

## 初步设计推论

若上述假设成立，Linear 的协作逻辑可能偏向“低噪声、状态即信号”：状态本身承载了大部分进度沟通，评论用于例外情况而非日常同步。这与强调文档沉淀或画布共创的产品可能存在明显取舍差异。该推论需要在横向比较阶段与其他三个产品对照后才能确认，当前不作为已核实结论。
