# Linear · 任务状态如何成为团队沟通

## 核心判断

Linear 最值得写进汇报的一点，是它把“状态变化”本身变成了团队沟通的一部分，而不是在任务之外再补一份进度报告。成员完成一次真实操作，进度就同步成为团队可见的信息，沟通被嵌进了工作流，而不是附加在工作流之上。

## 机制拆解

**状态即信号。** 任务状态不是静态标签，而是团队感知进展的主要载体。状态一变动，协作者就能读到“事情走到哪了”，无需额外同步。

**负责人、状态与项目周期绑定。** 三者直接挂在同一条任务上，使“谁在做、做到哪、什么时候要”成为同一份可读信息。责任与节奏因此不需要靠会议或文档二次确认。

**按需打断。** 常规推进不触发通知式沟通，只有出现偏差、风险或需要决策时才主动打断协作者。沟通的默认状态是安静，例外状态才发声。

## 对协作体验的启发

Linear 的取舍在于：用状态的结构化换取沟通的克制。它假设团队能通过状态字段读懂彼此，从而把大量“进度同步”从对话中省掉。这正好对照我们关心的“对话如何进入工作流”——Linear 给出的答案是反向的：让工作流的状态先承担沟通职能，对话只在状态无法表达时才介入。这一条可作为汇报中关于“减少无效同步”的支撑结论。
