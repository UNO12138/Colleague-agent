# Linear · 任务状态如何成为团队沟通

## 核心判断

Linear 的协作逻辑不是“先做任务、再写进度”，而是把任务状态本身当作团队沟通的载体。状态一变，信息就已经在团队里流动了，不需要额外补一份进度说明。这是它区别于“任务工具 + 沟通工具”组合方式的关键点。

## 状态即信号

在 Linear 中，任务状态（如待办、进行中、已完成等）不是个人备忘，而是对团队公开的协作信号。成员更新状态的动作，同时完成了两件事：推进自己的工作记录，以及向团队广播“这件事现在处于什么位置”。沟通被压缩进状态变更这一个动作里，而不是被拆成“改状态”和“同步进度”两步。

## 状态变化驱动感知

团队感知进度的方式，是观察状态的变化，而不是等待某人主动汇报。这意味着：

- 进度同步是持续发生的，不依赖例会或周报这类固定节点。
- 变化的可见性来自状态流转本身，谁改了什么、什么在推进，都能被直接看到。
- 沟通的触发点是“状态变了”，而不是“该汇报了”。

## 对协作体验的启发

Linear 的做法提示了一点：把沟通嵌入任务对象，比让成员在任务之外再维护一套同步动作更省力。状态字段在这里不只是分类标签，而是团队共享的进度语言。当状态变化天然可见时，团队对彼此工作的感知就从“被动询问”转向“主动浮现”。

## 本步结论

Linear 让任务状态承担了沟通职能：状态更新即进度同步，状态变化即团队感知的来源。它把“同步进度”这件事从额外动作变成了任务流转的副产品，这是其协作机制中最值得在汇报中强调的一条。
