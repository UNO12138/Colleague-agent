# 协作产品竞品调研 · 阶段草稿：Linear 的任务状态机制

## 本阶段的分析框架

本阶段聚焦 Linear，围绕“任务状态如何同时承担团队沟通与商业模式的角色”展开。初步设想从三个层面拆解：状态作为信息载体（谁在做什么、卡在哪里）、状态作为协作信号（变更如何被他人感知）、状态作为产品与商业设计的抓手（哪些能力被设为付费或团队规模相关）。以上为待验证的分析假设，尚未通过实际产品访问或文档核实。

## 待核实的问题

- Linear 的状态体系包含哪些层级（如工作流状态、周期、项目、优先级），它们之间如何联动，是否可自定义。
- 状态变更、评论、指派等行为以何种方式通知团队，是否存在聚合或降噪机制。
- 状态与进度同步的关系：进度是自动从状态推导，还是需要人工维护。
- 哪些协作能力与定价档位或席位规模相关，商业模式如何嵌入日常协作流程。
- 与 Notion、Figma、Miro 相比，Linear 在“状态即沟通”上的取舍是否更偏工程团队节奏。

## 阶段性设计推论（待验证）

若 Linear 以状态流转作为团队沟通的主干，则其协作体验可能更强调低噪声、强默认约定，而非开放式讨论。这一取向对汇报结论的启发是：协作产品的“状态感知”设计，可能需要在信息密度与打扰成本之间做明确取舍。上述推论需在完成实际调研后再确认或修正。
