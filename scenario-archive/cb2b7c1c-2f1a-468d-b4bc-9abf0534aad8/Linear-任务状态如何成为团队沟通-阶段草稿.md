# Linear · 任务状态如何成为团队沟通（阶段草稿）

## 本阶段的分析框架

本阶段聚焦一个核心问题：在 Linear 中，任务状态不只是记录进度的字段，而是否承担了团队沟通的职能。拟从三个维度拆解：

1. **状态作为信息载体**：状态本身传递了什么，谁负责更新，更新频率由什么驱动。
2. **状态作为同步机制**：状态变化如何被他人感知，是否需要额外通知或会议补充。
3. **状态作为协作边界**：状态与评论、指派、优先级之间的关系，是否替代了部分对话。

## 待核实问题

- Linear 的状态集合是否为固定默认值，还是可由团队自定义；默认状态的具体名称与数量待核实。
- 状态变更是否会触发订阅者通知，通知渠道与粒度待核实。
- 状态与评论是否在同一视图内联动，评论是否可绑定到具体状态变更待核实。
- 是否存在“状态停滞”类的提醒或自动化规则，待核实。

## 初步设计推论（待验证）

- 若状态变更默认对相关成员可见，则状态可部分替代“进度同步”类沟通，减少显式汇报。
- 若状态与评论强绑定，则讨论会围绕任务对象沉淀，而非散落在聊天工具中。
- 若状态可自定义，则团队可能用状态表达流程语义，而非仅表达完成度。
